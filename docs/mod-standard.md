# Стандарт мода WTE_QOL_*

Формат папки мода, документации и релизов. Цель: у любого мода всё для публикации уже лежит в его папке (Nexus-текст, ченджлог, README), а релиз на GitHub делается одной командой.

Новый мод начинаем с копии шаблона:

```bash
cp -r tools/mod-template mods/WTE_QOL_<Name>
```

Затем заменить все `Template`/`mod_template` на своё имя (папка, `name` в mod.json, `LOG_FILE`, тег лога `[Template]`, MOD_VERSION в плагине) и заполнить тексты.

## Структура папки мода

```
mods/WTE_QOL_<Name>/
├── mod.json                  # name, author, version, description, priority
├── js/plugins/<name>.js      # IIFE, alias_<Класс>_<метод>, CONFIG в начале файла
├── README.md                 # русский
├── README_EN.md              # английский (для Nexus/публикации)
├── CHANGELOG.md              # английский, секции "## <версия>", новые сверху
├── nexus-description.bbcode  # готовый текст страницы Nexus (см. ниже)
├── .gitignore                # одна строка: logs/
└── logs/                     # рантайм-логи, в git НЕ попадают, в архив НЕ попадают
```

Обязательны все файлы, кроме `logs/` (создаётся самой игрой). Чужие файлы (сейвы, скриншоты для Nexus) в папку мода не кладём — в архив уйдёт всё, что там лежит.

## Документация внутри мода

- **README.md / README_EN.md** — по шаблону: что даёт → требования → установка (3 шага, включая включение VirtualModLoader) → настройка (таблица CONFIG) → логи → автор. Держим синхронно по смыслу, не дословно.
- **CHANGELOG.md** — ведётся на английском (это готовое тело GitHub-релиза). Формат: заголовок `# Changelog — <ModName>`, строка про схему версий, дальше секции `## <версия>` (новая сверху), внутри — буллеты по одному на изменение, язык — что поменялось для игрока, без внутренних деталей реализации. Секцию пишем в том же коммите, что и код, — релизный скрипт без неё не сработает.
- **nexus-description.bbcode** — готовый текст страницы Nexus в двух частях: `SHORT DESCRIPTION` (поле Summary, одно предложение без BBCode) и `FULL DESCRIPTION` (поле Description, BBCode). Секции Installation/Uninstall/Troubleshooting/Credits универсальны — в шаблоне уже написаны, меняется только имя папки и файла лога. При обновлении страницы на Nexus текст берётся отсюда целиком, а не наоборот: файл в репо — источник истины.

## Версия

Схема `<версия игры>.<ревизия мода>` (`1.0.2a.5`). Стоит ровно в двух местах и обязана совпадать — `mod.json` → `version` и `MOD_VERSION` в плагине (она уходит в лог поддержки). Скрипт релиза падает при расхождении.

## Релиз (GitHub)

Одна команда из корня репо:

```bash
tools/release_mod.sh WTE_QOL_<Name>            # полный флоу
tools/release_mod.sh WTE_QOL_<Name> --no-github # только коммит, тег, zip
```

Скрипт сам:

1. Валидирует `mod.json`, совпадение версий и баланс скобок плагинов; требует секцию `## <версия>` в CHANGELOG.md.
2. Коммитит папку мода (`release: v<версия>`) и ставит аннотированный тег `v<версия>-<shortname>`.
3. Собирает `dist/<ModName>-v<версия>.zip` со структурой `mods/<ModName>/...` (без `logs/`) — такой архив распаковывается прямо в папку игры.
4. Пушит коммит и тег.
5. Создаёт GitHub release по тегу: название `WTE_QOL_<Name> v<версия>`, тело — секция из CHANGELOG.md, ассет — zip. Токен берётся из git credential (тот же, что для push), в скрипте и репо не хранится.

Повторный запуск безопасен: существующие тег/release не дублируются, ассет перезаливается. Флаг `--pre` помечает релиз как prerelease.

Перед релизом версию бампим отдельным коммитом (или тем же, что правки) — скрипт версии сам не поднимает.

## Nexus

Публикация/обновление страницы — ручное: Summary и Description копируются из `nexus-description.bbcode`, файлы и скриншоты заливаются руками. В zip для Nexus идёт тот же архив из `dist/`, что и на GitHub.
