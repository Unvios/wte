# WTE Mod Loader

Исходники: `js/plugins/VirtualModLoader.js` (351 строка, весь лоадер) и
`js/plugins/ModLoader_Injector.js` (генерируемый файл-инжектор).
Оба стоят в `js/plugins.js`: VirtualModLoader — вверху списка, инжектор — в самом низу.

## Структура мода

```
mods/MyMod/
  mod.json            ← {"name","author","version","description","priority"}
  js/plugins/*.js     ← плагины, автоинъекция
  data/*.json         ← splice-файлы (modded*) и полные оверрайды
  img/**, audio/**    ← замена/добавление ресурсов
```

- Папки с `!` в начале имени пропускаются.
- `priority` (default 0): **ассеты** ищутся от большего приоритета к меньшему
  (первый найденный wins), **плагины и сплайсы** применяются от меньшего к
  большему (последняя запись побеждает).

## Как инжектятся плагины

При каждом запуске лоадер читает все `mods/*/js/plugins/*.js`, склеивает их
в один `js/plugins/ModLoader_Injector.js` и дописывает вокруг fail-safe блок
`if (window.VirtualModLoader.active)`. Если содержимое инжектора изменилось
(добавился/удалился мод или правился плагин) — файл перезаписывается и игра
сама делает `location.reload()`.

Следствия:

- **Мод-код выполняется после всех базовых плагинов** → переопределения
  прототипов в модах побеждают базовые.
- **`PluginManager.parameters()` для мод-плагинов НЕ работает** — они не
  регистрируются в менеджере плагинов. Конфигурацию хардкодим объектом внутри
  своего файла.
- Все мод-плагины склеиваются в одну область видимости: **оборачивайте код в
  IIFE** и давайте алиасам уникальные имена (`alias_<Класс>_<метод>` — конвенция).
- Словили баг «мод не обновился» — смотреть, не выставлен ли
  `ModLoader_Injector.js` в read-only.

## Data splicing (рекомендуемый способ менять данные)

Файл `mods/<mod>/data/modded<Имя>.json` вливается в одноимённый базовый файл
при загрузке (`applyModDataSplices` в VirtualModLoader).

- **Массивы БД** (Items, Weapons, Armors, Actors, Classes, CommonEvents,
  Enemies, Troops, Skills, States, System): элемент заменяется **целиком** по
  своему `id` (`coreData[id] = modItem`). Не deep-merge! Копируем полный объект
  и меняем нужные поля.
- **Карты** (`moddedMap002.json` и т.п.): пословный merge корневых полей,
  массив `events` мерджится по `id` события (можно добавлять новые события).
- Формат: валидный JSON; каждый корневой элемент/событие — **одной строкой**
  (так хранит их сам MZ, лоадер этого ждёт).

```json
[
null,
{"id":2043,"name":"Cup of Coffee", ...}
]
```

Полный оверрайд (файл с точным именем базового, без префикса `modded`)
заменяет весь файл игры — работает, но ломается от любого обновления и
конфликтует с другими модами. Избегать.

## Ресурсы (img/audio)

Достаточно повторить путь: `mods/MyMod/img/system/MenuBG.png` перехватит
загрузку `img/system/MenuBG.png`. Картинки инжектятся как base64-data-URI,
аудио читается в ArrayBuffer и подкладывается в WebAudio (есть фолбэк
`.ogg` ↔ `.m4a`). Имена файлов регистрозависимы, ищется точное совпадение.

## Отладка

- Лоадер пишет в консоль тегом `[Mod Loader]` (состав модов, splice-ы, ошибки
  парсинга JSON модов).
- В плагинах модов `console.log` попадает в консоль NW.js (F12 / Ctrl+Shift+I,
  если DevTools не отключены сборкой).
- Путь к папке игры из плагина: `path.dirname(process.mainModule.filename)`.
