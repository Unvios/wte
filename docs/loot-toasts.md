# Лут после боя → тосты (WTE_QOL_Loot_Toasts)

Разобрано при разработке мода `mods/WTE_QOL_Loot_Toasts/` (октябрь 2026).

## Цепочка лута после боя

1. **Триггер**: `CGMZ_BattleResultEvents` после каждого боя резервирует общее событие
   **CE 27** «Battle Win» (`js/plugins.js:87`: Troop ID→var 22, Result→var 23,
   CE 27). Резервированное CE исполняется на интерпретаторе карты
   (`js/rmmz_objects.js:9541`). CE 27 никто больше не вызывает — это единственная
   точка входа лут-потока.
2. **CE 27**: переменная 2 = случайное 1–100. ≥ 50 — «труп цел»: картинка
   `Obj_DEATHLOOT` (№5), тексты, затем ~40 веток «Call Common Event» по var 22 —
   лут-таблицы (CE 551…1745). Иначе — «труп изуродован». В конце — автосейв.
3. **Лут-таблицы**: CE 36 «Roll Die 1-6» → CE 35 «Roll Die Math» (финальный бросок
   в var 2 + бонусы от Crimson Die/Lucky Die/Slayer's Ring) → **CE 28 «Dice Roll
   Effect»** (анимация: крутит `d1..d6` на картинках №9/10 с ~50 wait-командами —
   сами паузы блокируют движение игрока) → CE 29–34 «Dice Result 1..6» (итоговая
   грань `d1..d6` картинкой №11, баннер `Luck_*` №12, SE и **пустое сообщение-
   пауза**). Спецдропы выдаются прямо (`127/128`) с текстом «Obtained \c[14]X»;
   обычный дроп — через **CE 12** «Check and Give Item» (var 30 = id предмета,
   var 31 = количество → скрипт `gainItem` → «Obtained \C[6]\ii[\V[30]] \C[0]x\V[31]»,
   при нехватке места — CE 862 и «No space in bag…»); золото — **CE 599**; материалы —
   **CE 595** (часть строк — «You find N gold.» в самих таблицах 562/567/563).

## Почему сообщения блокируют

`Game_Interpreter.prototype.command101` (`js/rmmz_objects.js:9789`) заполняет
`$gameMessage`, вызывает `setWaitMode("message")` (9816) и интерпретатор стоит, пока
окно не прокликают. Каждый предмет = новое окно = новый клик.

## Как работает мод (плагин без правок данных)

- **Контекст**: спуск от `$gameMap._interpreter` по `_childInterpreter`; если чей-либо
  `_list` ссылочно равен `$dataCommonEvents[27].list` — мы в лут-потоке. Новые лут-CE
  от обновлений игры покрываются автоматически; смена номера CE 27 = fail-safe
  (молча ванилла).
- **command101** в контексте: строки 401 собираются, пустое сообщение (пауза грани
  кубика) → значение броска запоминается в `rollFace` и идёт в сводный тост.
  Тексты про состояние трупа не показываются (`SUPPRESSED_TEXTS`). Wait-режим не
  ставится → управление возвращается сразу. Вне контекста — ванильный алиас.
- **Победа**: `BattleManager.displayVictoryMessage` / `displayExp`
  (`js/rmmz_managers.js:2975,2998`) — ванильные окна «Victory!» и «Obtained:
  N EXP!» после боя. Оба глушатся (`VICTORY_EXP_TOAST`); сумма ОП запоминается
  (`pendingExp`) и уходит в сводный тост. Слово «EXP/ОП» — из терминов игры,
  строк мода нет.
- **Батчинг**: сообщения лут-потока не ставят тосты сразу, а копятся в
  `lootBatch` (`{kind: plain|item|gold, text, amount, shrine}`). Когда
  цепочка CE 27 завершается (хук в `Game_Map.update`), золото суммируется,
  остальное сортируется и сливается в очередь одним проходом. Порядок снизу
  вверх: предметы святилища → обычные предметы → сводный тост (сортировка
  стабильная, внутри группы — хронология). Сводный тост наверху стека собирает:
  грань выпавшего кубика — картинка `dN` рисуется в `processCustomToast` слева,
  текст со сдвигом (`_wteSummaryFace` = `rollFace`), ОП (`pendingExp` из боя +
  `TextManager.exp`), золото (сумма `amount` записей gold) — части разделены
  `SUMMARY_SEPARATOR`, отсутствующие опускаются («[грань]  16 ОП  [coin]34»,
  «16 ОП», «[coin]34»…). Награда святилища — флаг `shrine` на записях; в
  `refresh` тоста 8 спрайтам рамки (`_frameSprite.children`) ставится золотой
  `tint` — оригинальная рамка windowskin сохраняется, перекрашена множительно
  (при переиспользовании слота tint сбрасывается в 0xFFFFFF).
- **Награда боевого святилища**: сообщение «The combat shrine rewards you...»
  (CE 2707/2708/2709, эмпавер-лут через CE 2704 ← CE 595) не показывается; при
  его перехвате взводится флаг, и весь следующий дроп до конца лут-потока
  помечается флагом `shrine` → золотая рамка тоста. Флаг сбрасывается
  в алиасе `Game_Map.prototype.update`, когда цепочка CE 27 завершена.
- **Начало боя**: сообщения отрядов «A Rat appears!» / «A Cute Flower attacks!»
  (Troops.json, code 401) в сцене боя пропускаются целиком
  (`REMOVE_BATTLE_START_MESSAGES`): короткая строка с артиклем в начале и
  глаголом appear/attack/emerge/approach по сырому англ. тексту до перевода.
- **Формат тостов дропа собирается из данных, а не из строк** — слово «Получено»
  у переводов разного порядка (de — суффикс «erhalten!», fr — «Vous obtenez
  l'…»), поэтому обрезка перевода хрупкая. Вместо этого: CE 12 (переменные
  30/31) → `\c[6]\ii[id]\c[0]` (+` xN` при N>1); золото CE 599 (var 1039) →
  запись `kind: 'gold'` с `amount`, сумма уходит в сводный тост; спецдропы —
  трекинг `command126/127/128` → `\i[icon]\c[14]{локализованное имя}\c[0]`.
  Локализация имён — из БД предметов. Мод не хранит ни одной игровой строки.
- **command117**: CE 28 «Dice Roll Effect» пропускается целиком — это анимация
  броска (картинки 9/10 + ~50 wait), паузы которой сами по себе морозили
  движение игрока, а без пауз её ~20 тиковых SE сыграли бы в одном кадре.
- **Тосты**: `$cgmzTemp.createNewToast` (`CGMZ_ToastManager.js:1593`). Сырые англ.
  строки из событий матчат CSV `Original` байт-в-байт, поэтому перевод и снапшот
  `\V[n]` в момент постановки делает базовый `Toast_Localization_Fix.js` (иначе был
  бы баг: var 30/31 перезаписываются следующими роллами до отрисовки тоста).
  Рисуются через `CGMZ_drawTextLine` → полная обработка `\ii`/`\i`/`\c`.
  Окно тоста однострочное (Fixed Height) → многострочные сообщения склеиваются.
- **Позиция справа**: алиас `CGMZ_Window_Toast.prototype.refresh` по маркеру
  `_wteLootToast` (глобально у игры center/bottom — `CGMZ_ToastManager.js:1971`).
  Вертикальный стек ванильный (снизу вверх): первый предмет в нижний слот,
  сводный тост ставится последним — оказывается наверху. Страховка: сообщение с
  выбором (102/103/104) следом — ванильное окно, иначе тост съел бы текст у
  выбора.
- **Картинки**: 231/232/235 с номерами {5, 11, 12} пропускаются в контексте
  (вместе с фейд-wait в CE 27); SE броска остаются.
- **Очередь**: 3 слота, «queue accelerator» из Toast_Localization_Fix выталкивает
  самый старый тост при переполнении; `CGMZ_ToastDuplicateClear.js` схлопывает
  полностью одинаковые тосты (косметика — предметы уже выданы). Сводный тост
  ставится последним, поэтому при быстром скролле очереди он живёт дольше всех.

## Инварианты

- Игровые строки мод не хранит вообще (тосты дропа собираются из БД предметов) →
  рисков с ключами локализации нет.
- Консоль (F12) в этой сборке недоступна; при `DEBUG: true` мод пишет лог в
  `loot_toasts_debug.log` в корне игры.
- Сироты CE 2447/2448/2994 (петы/рыбалка, никем не вызваны) и всё вне CE 27 —
  ванилла.
- Выключение мода (префикс `!` у папки) возвращает игру к оригиналу целиком.
