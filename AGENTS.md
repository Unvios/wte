# AGENTS.md — моддинг Welcome to Elderfield

Репозиторий — моды для игры Welcome to Elderfield (RPG Maker MZ, рантайм NW.js). Игровая сборка целиком в git; моды живут в `mods/`, база знаний — в `docs/`.

## С чего начать (в порядке чтения)

1. `docs/README.md` — оглавление и базовые факты движка.
2. `docs/mod-loader.md` — как грузятся моды: инъекция плагинов, splice-формат, приоритеты.
3. Задача связана со временем/баффами → `docs/timed-states.md`.
4. Задача касается текстов/перевода → `docs/localization.md` (обязательно: там неочевидные пути перевода и проверенный паттерн обёрток).
5. Официальный гайд разработчиков: `mods/How to Mod.txt` (дублирует docs/mod-loader.md).
6. Новый мод или релиз → `docs/mod-standard.md` (структура папки, доки, релизный скрипт).
7. Автотесты / проверка модов роботом → `docs/e2e-testing.md` (E2E-харнес на CDP поверх NW.js SDK).

Эталон реализации всех паттернов: `mods/WTE_QOL_Coffee_Duration/` (таймер состояния + многоязычные тексты через обёртки).

## Железные правила

- **Не править оригинальные файлы игры.** Единственное задокументированное исключение: `js/plugins.js` → `VirtualModLoader` включён (`status: true`) — без него моды не грузятся вообще. Файл игры в репозиторий не коммитим (правка теряется при обновлении — восстанавливать скриптом `tools/enable_mod_loader.sh`). Обновления также могут затереть `mods/` — поэтому моды и доки держим в git.
- Новый мод = новая папка `mods/<ModName>/` с `mod.json` (`name`, `author`, `version`, `description`, `priority`), начинаем с копии `tools/mod-template/` (см. `docs/mod-standard.md`).
- Плагины модов: оборачивать в IIFE, алиасы называть `alias_<Класс>_<метод>`, конфигурацию хардкодить внутри файла — `PluginManager.parameters()` для мод-плагинов не работает.
- Данные менять через splice (`data/modded<Имя>.json`), НЕ полными копиями базовых файлов. Помнить: элемент массива заменяется целиком по `id`.
- Строки, существующие в `game_messages.csv`, не менять в `data/*.json` — сломаются ключи локализации. Использовать паттерн обёрток из `docs/localization.md`.
- **Каждый мод — самостоятельная единица.** Моды не должны зависеть друг от друга (код, состояние, строки, логи): любой мод из `mods/` включается и выключается отдельно, и в его отсутствие игра не падает и не теряет чужие функции. Чужие моды не правим вообще — включая соседние свои `WTE_QOL_*`: предложение по чужому моду = сообщение владельцу, а не правка (и наоборот: в свой мод не копируем код чужого — только паттерны из `docs/`). Интеграция с плагинами самой игры допустима, но только через их публичное состояние/методы и с гардами (`typeof x === 'function'`, проверки полей) — без плагина-цели мод обязан молча деградировать (фолбэк или отказ с логом), а не падать.

## Стиль доков

- Markdown пишем без жёстких переносов строк: один абзац / пункт списка / строка таблицы = одна строка. Переносы только между блоками (заголовок, пункт, строка таблицы, код-блок). Не «форматировать» текст столбиком под 80 символов — переносит редактор.

## Окружение и инструменты

- Windows + Git Bash. `node` установлен (v24, `D:\programs\nodejs`; если шелл старый — полный путь `/d/programs/nodejs/node.exe`), `python`, `jq` в PATH отсутствуют.
- Валидация JSON: `perl -MJSON::PP -e '...'` или `node -e 'JSON.parse(...)'`.
- Синтаксис JS перед коммитом: `node --check файл.js` (предпочтительно) либо perl-подсчёт скобок с пропуском строк/комментариев: `perl tools/balcheck.pl < файл.js`. Perl-код писать в файл, не инлайн — Bash-инструмент агента съедает один уровень бэкслешей в командной строке.
- Поиск по коду: `grep`/ripgrep; учесть, что VisuMZ-*.js обфусцированы — смысл из них не вытащить, методы патчатся «слепо» по именам классов MZ.

## Проверка модов

1. Запустить `Game.exe` — лоадер сам пересобирает `js/plugins/ModLoader_Injector.js` и один раз перезагружает игру.
2. Консоль (F12/Ctrl+Shift+I): логи лоадера с тегом `[Mod Loader]`, наш эталонный мод пишет `[CoffeeDuration]`.
3. Ачивки Steam модами не отключаются (проверено: `Cyclone-Steam.js` шлёт `greenworks.activateAchievement()` безусловно).
4. Автоматические E2E-прогоны: `tools/e2e/run.sh tools/e2e/scenarios/smoke.mjs` — игра запускается под NW.js SDK с CDP-портом, сценарий проверяет состояние через JS. Сейвы под защитой: раннер откатывает любые изменения `save/`. Подробности и API сценариев — `docs/e2e-testing.md`. Важно: штатный `Game.exe` — non-SDK сборка NW.js, CDP-порт на нём не открывается вообще, поэтому харнес работает только через `tools/nwjs-sdk/nw.exe`.
5. У каждого своего мода должен быть тест-план с кейсами: `docs/e2e-<mod>-testplan.md` (эталон — `docs/e2e-hotbar-testplan.md`), затем сценарии `tools/e2e/scenarios/<префикс>-*.mjs`. Уровни проверок и рецепты — раздел «Покрытие модов тестами» в `docs/e2e-testing.md`. Перед релизом — зелёный `tools/e2e/run_suite.sh <префикс>`. Каждый кейс обязан пройти негативную проверку: вносим целевой баг в мод → сценарий краснеет на этом кейсе → баг откатываем → зелёный (иначе ассерт ничего не доказывает).

## Версионирование и релизы

- Схема версии мода: `<версия игры>.<ревизия мода>` — `1.0.2a.1` = сборка под игру 1.0.2a, ревизия 1. Смена версии игры сбрасывает ревизию (игра 1.0.3 → первая сборка `1.0.3.1`).
- Версия стоит в двух местах и обязана совпадать: `mod.json` (`version`) и константа `MOD_VERSION` в плагине (она уходит в лог поддержки — по логу на чужой машине видно, какая сборка стоит).
- Флоу релиза — скрипт `tools/release_mod.sh <ModName>` (см. `docs/mod-standard.md`): сам валидирует версии и синтаксис, требует секцию в CHANGELOG.md, коммитит `release: v<версия>`, ставит аннотированный тег, собирает `dist/<ModName>-v<версия>.zip` (структура `mods/<ModName>/`, без `logs/`), пушит и создаёт GitHub release с телом из ченджлога и zip-ассетом. Вручную (без скрипта) релизы не делаем. Nexus-текст всегда берётся из `nexus-description.bbcode` в папке мода — файл в репо источник истины, не страница.
- Имя тега: `v<версия>-<shortname>` (например `v1.0.2a.1-hotbar`, `v1.0.2a.1-loot-toast`); скрипт выводит shortname из имени папки. В репо несколько модов с независимыми версиями — голый `v<версия>` не используем; переназначать чужой тег нельзя.

## Структура репозитория

- `mods/` — моды (`!`-префикс = выключен). В git трекаются только свои моды с префиксом `WTE_QOL_*` (правило `!/mods/WTE_QOL_*/`); чужие моды из `mods/` в репозиторий не попадают. Для своего мода с другим именем добавь исключение в `.gitignore`.
- `docs/` — документация по движку (см. выше).
- `tools/` — вспомогательные скрипты (`enable_mod_loader.sh` — вернуть работу модов после обновления игры; `release_mod.sh` — релиз мода: коммит, тег, zip, GitHub release; `mod-template/` — шаблон нового мода; `e2e/` — E2E-харнес на CDP, см. `docs/e2e-testing.md`; `nwjs-sdk/` — SDK-сборка NW.js для тестов, вне git).
- `AGENTS.md` — этот файл-навигатор.
- `js/plugins.js` и всё остальное — файлы игры, в репозиторий не попадают.
